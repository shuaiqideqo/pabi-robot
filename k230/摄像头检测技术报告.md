## 3.1 引言

### 3.1.1 工程背景与检测任务

本文研究的管道内壁作业机器人系统由母机（ESP32-S3）、子机（STM32F103RCT6 管道爬车）与视觉板（K230 CanMV）三端组成。子机在协同作业周期中执行"下行 → 探头下压作业 → 回程"的运动序列。由于子机采用 IMU 航向闭环 + 编码器里程计的开环式回程定位，且周向/姿态向的微小滑动无法被 IMU 观测（见固件文档《子机现状说明》§5），子机回到作业位姿后不可避免地存在残余位姿偏差。该偏差可分解为三个自由度：

- **φ（周向滚转角）**：子机绕管道轴线的滚转角偏差，决定探头在管壁周向上的落点误差；
- **ψ（航向角 / 歪头角）**：子机自身朝向相对管道轴线的面内偏转；
- **ax（轴向滑移）**：子机沿管道轴线方向的平移偏差。

三者若不纠正，探头将偏离既定检测点，导致声发射（AE）检测位置失准。因此系统在回程结束后引入**视觉纠偏闭环**：由摄像头检测子系统实时测量上述三自由度偏差，经母机换算为运动指令下发子机执行，迭代直至收敛。

### 3.1.2 检测需求分析

根据闭环控制指标与现场部署条件，摄像头检测子系统需满足以下需求：

| 需求项 | 指标 / 约束 | 来源 |
|---|---|---|
| 测量自由度 | φ、ψ（角度）与 ax（长度）三自由度，符号方向明确 | 闭环控制要求 |
| 测量精度 | 支撑 ±0.5°（φ/ψ）、±2 mm（ax）级收敛判据 | `ALIGN_ANGLE_TOL_DEG` / `ALIGN_AXIAL_TOL_MM`（代码 37–38 行） |
| 单次测量时延 | ≤ 0.5 s（闭环每轮测量节拍受 `AV_POLL_MS=500` 约束） | 母机 `firmware/config.h` |
| 抗遮挡 / 抗误检 | 单枚标志被遮挡时仍能降级输出测量值 | 返程工况中夹爪可能遮挡一枚码 |
| 系统集成 | 以 HTTP/JSON 服务化接口供母机与 App 调用，同时提供实时画面 | `ALIGN_CODE_MAP.md` §1 |
| 功耗 | 闲置时摄像头断电，仅保留网络服务 | 电池供电约束 |
| 可维护性 | 几何常数集中定义、跨端一致；现场免重编译完成符号标定 | 联调经验 |

## 3.2 检测方案总体设计

### 3.2.1 基准标志方案论证

视觉位姿测量需要图像中存在具有已知几何的基准。候选方案对比：

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 自然特征匹配（SIFT/ORB 等） | 无需布设标志 | 管内壁纹理弱、光照不均，匹配不稳定；算力开销大 | 否决 |
| 棋盘格 / 圆点标靶 | 检测简单 | 无编码能力，无法区分身份与方向；遮挡后不可恢复 | 否决 |
| **AprilTag 二维基准码** | 编码唯一 ID、汉明纠错抗误检、角点定位精度亚像素级、开源检测库成熟（CanMV 内置 `find_apriltags`） | 需在场景中布设打印标志 | **采用** |
| 二维码（QR） | 信息量大 | 定位精度与实时性不及 AprilTag，专为存储设计 | 否决 |

在单码与**双码**之间，本设计选择双码方案，理由如下：

1. **比例尺自标定**：两码中心间距固定为 40 mm（`DUAL_TAG_SEP_MM`，代码 31 行），由基线像素长度即可解算毫米/像素比例尺，不依赖单码 15 mm 边长的透视投影估计——基线比边长更长（实测参考位基线约 96 px，对应码边长约 36 px），同样的角点噪声下比例尺相对误差更小；
2. **方向基准**：基线方向直接给出图像内管道轴向与面内朝向 ψ，且参考位在标定时"吸收"了相机安装旋转误差（详见 3.4.1）；
3. **冗余与降级**：两码互为备份，任一码被遮挡时可依据标定期记录的刚体偏移量由单码反推整机位姿（3.3.4），保证返程测量不中断。

### 3.2.2 检测平台选型

视觉板采用嘉楠 Kendryte **K230 CanMV** 开发板（亚博科技版，板载 WiFi）。选型依据：

- **算力**：双核 RISC-V 处理器（最高 1.6 GHz），可在 640×480 分辨率下实时完成 AprilTag 检测与 JPEG 编码，满足 0.5 s 测量节拍；
- **软件生态**：CanMV 固件提供 OpenMV 兼容的 `image.find_apriltags()` 视觉库与 MicroPython 运行时，算法迭代无需交叉编译；
- **通信**：板载 WiFi 支持 STA/AP 双模，可直连平板热点与母机同网段，HTTP 服务可直接被母机（ESP32-S3）与 App（Android WebView）访问；
- **功耗可控**：支持传感器级停采（`sensor.stop()`），配合软件策略实现闲置断采。

### 3.2.3 系统组成与数据流

摄像头检测子系统在整机视觉纠偏链路中的位置如下：

```
[K230 CanMV 视觉板] --HTTP :80 /align/*--> [母机 ESP32-S3 align_vision 状态机]
   |  双码检测 → 偏差解算        |  收敛判定 → 增益/限幅 → ADJ 帧
   |  :81/stream MJPEG          v
   v                      NRF24L01 (32B 定长)
[App Android WebView]              v
   监视轮询 /align/get      [子机 STM32F103 Adj_Execute 三段式运动]
   (φ/ψ/ax 实时显示)
```

数据通道分工（改链路时不得混淆）：

| 数据 | 通道 |
|---|---|
| 视觉测量值（φ/ψ/ax，JSON） | App ↔ K230 直连 HTTP；母机 → K230 `/align/once` |
| 子机运动指令（ADJ 帧） | App → 母机 WS → NRF → 子机 |
| 闭环状态回传（0x88/0x89） | 母机 → App WebSocket |
| 子机画面 | K230 `:81/stream` 直连 App `<img>` |

K230 单文件实现全部板端逻辑（检测、解算、服务、发现协议），部署为板端 `/sdcard/main.py` 上电自启。

## 3.3 目标检测算法设计

### 3.3.1 AprilTag 检测流程

检测采用 tag36h11 族（`TAG_FAMILIES = image.TAG36H11`，代码 75 行），该族在 36 位编码空间内具有较大码字容量与汉明间距，兼顾解码鲁棒性与码面尺寸。检测输入为 640×480（`DETECT_WIDTH/HEIGHT`，代码 73–74 行）帧，先经 `img_for_detect()` 转灰度（代码 988 行）以减半数据量，再调用 `gray.find_apriltags()`。其内部流程为经典 AprilTag 管线：

1. **自适应阈值分割**：对灰度图局部自适应二值化，抑制管内光照不均；
2. **连通域与四边形检测**：提取连通域聚类，拟合四边形候选；
3. **透视展开与位采样**：对候选四边形做单应变换，采样码格比特；
4. **码字解码与纠错**：在 tag36h11 码表中检索最近码字，输出 ID 与汉明距离（错误比特数），汉明距离同时作为解码置信度指标。

### 3.3.2 单码观测向量提取

`obs_from_apriltag()`（代码 231 行）将库返回的标签对象规约为统一观测向量：

```
obs = { id, u, v, theta, edge_a, edge_p, hamming }
```

其中：

- `(u, v)`：码中心像素坐标（`cx(), cy()`）；
- **θ（面内朝向）**：取四角点中 `c0→c1` 连线的方位角，`theta = atan2(c1y − c0y, c1x − c0x)`；若角点接口不可用则退化为 `tag.rotation()`。θ 的绝对值依赖库的角点排序约定，但参考位与测量帧采用同一约定，差值具有一致的物理意义；
- **edge_a（轴向边长）**：`c0c1` 与 `c2c3` 对边长度的均值；**edge_p（横向边长）**：`c1c2` 与 `c3c0` 对边长度的均值。二者用于透视收缩交叉校验（3.4.2）；
- **hamming**：解码汉明距离，0 表示无错解码。

同一 ID 出现多个候选时取 `edge_a` 最大者（`detect_dual_from_tags()`，代码 331–339 行）——边长最大意味着距离最近、角点信噪比最高。

### 3.3.3 双码融合观测

`fuse_dual_obs()`（代码 184 行）将两枚码（按 ID 排序为小 ID `lo`、大 ID `hi`）融合为一个刚体观测：

- **融合中心**：两码中点的像素坐标 `(mid_u, mid_v)`；
- **基线方向**：`θ = atan2(hi_v − lo_v, hi_u − lo_u)`，即小 ID → 大 ID 连线方位角；
- **基线长度**：`dist = ‖hi − lo‖₂`（像素），作为融合观测的等效边长；
- **比例尺**：`scale = DUAL_TAG_SEP_MM / dist`（mm/px），由 40 mm 已知基线自标定；
- **刚体偏移标定量 `tag_off`**：每枚码相对融合中点在"基线坐标系"（x 轴沿基线、y 轴垂直基线）下的偏移：

  along = ((mid_u − u_t)·cosθ + (mid_v − v_t)·sinθ)·scale
  perp  = (−(mid_u − u_t)·sinθ + (mid_v − v_t)·cosθ)·scale

  该量在记参考时随参考位一并存储，是单码反推（3.3.4）的先验；`along_mm` 的正负由实测决定，不写死符号，从而兼容两码前后贴反的安装误差。

融合观测的 `hamming` 取两码较大值（保守），保留 `id / id_b` 以便上层追溯。

### 3.3.4 单码刚体反推（鲁棒性扩展）

返程工况中，夹爪或视角可能遮挡其中一枚码。为避免测量中断，本设计（当前工作区新增，未提交）在已有参考位的前提下支持**单码降级测量**：`synthesize_dual_from_one()`（代码 286 行）基于刚体假设由可见单码反推融合中点：

1. 取标定期该码的刚体偏移 `off = ref.tag_off[id]`；
2. 由当前码朝向与标定朝向之差恢复基线当前方向：
   `dθ = wrap_pi(θ_tag − off.theta)`；若 `|dθ| > π/2` 则取 `dθ = wrap_pi(dθ + π)`（处理码面 180° 观察歧义），`θ_now = wrap_pi(ref.theta + dθ)`；
3. 以**可见码自身边长**恢复比例尺：`mm_per_px = TAG_REAL_MM / edge_a`（单码无基线，退回 15 mm 码边长标定）；
4. 反推中点：
   `mid = tag_pos + (along·e_ax + perp·e_pp) / mm_per_px`，其中 `e_ax = (cos θ_now, sin θ_now)`、`e_pp` 为其法向；
5. 以 `sep_px = 40 / mm_per_px` 构造等效基线长度，输出与双码融合同构的观测，并标记 `tags_used = 1`。

降级路径的启用规则体现了"标定从严、测量从宽"的原则：

- **记参考（/align/ref）强制 `allow_single=False`**：标定必须来自真实双码，防止单码反推误差进入参考基准（代码 1557 行）；
- **测一次（/align/once）与预览检码允许 `allow_single=True`**：仅在参考位已存在时生效（代码 1146–1148 行）。

测量结果 JSON 中以 `"tags"` 字段（2/1）显式标注本次测量使用的码数，供上位机评估置信度。

### 3.3.5 失效模式与处理策略

检测层定义了显式的失效原因码，随 JSON 上报：

| 原因码 | 触发条件 | 处理 |
|---|---|---|
| `no_tag` | 帧内未检出任何目标码 | 上层重试（共识窗口内继续取帧） |
| `need_two_tags` | 仅见一码且不允许/无法单码反推 | 返程接近参考位时通常可见双码，属瞬态 |
| `no_ref` | 未记参考即请求测量 | 拒绝并提示先标定 |
| `not_running` | 摄像头未开启 | `/align/ref`、`/align/once` 会自动唤醒采集 |
| 共识超时 | 5 s（`CONSENSUS_TIMEOUT_MS`）内未凑满 N 帧有效观测 | 返回最后原因码，闭环侧按测量失败重试 |

## 3.4 位姿偏差解算模型

### 3.4.1 参考位与坐标系定义

**坐标系约定**（图像坐标系，u 向右、v 向下）：

- **管道轴向单位向量** `e_ax = (cos θ₀, sin θ₀)`，**周向单位向量** `e_pp = (−sin θ₀, cos θ₀)`，其中 θ₀ 为参考位融合基线方位角；
- **粘贴约定**：双码中心连线（ID0→ID1）平行于管道轴线粘贴，40 mm 间距沿轴向排列。该约定使基线方向即管道轴向在图像中的投影方向。

**参考位标定**：子机下行到位、母机夹爪对中后，由 App 经母机透传调用 `GET /align/ref`。K230 在 5 s 时限内连续取帧检测，**强制双码**（`allow_single=False`），凑满 `ALIGN_FRAMES` 帧共识后以均值建立参考位：

```
ref = { u₀, v₀, θ₀, edge_a₀, tag_off }
```

由于 θ₀ 取自参考时刻实测基线方向，**相机安装的任意面内旋转角被参考位自然吸收**——后续所有偏差均以 θ₀ 定义的方向为基准，无需精确调校相机安装角。这是该模型在工程部署上的一个重要优点。

### 3.4.2 偏差解算公式

`delta_report()`（代码 137 行）以当前融合观测 `tag = {u, v, θ, edge_a, …}` 与参考位 `ref` 解算偏差。设当前帧比例尺

$$s = \frac{L_{base}}{\|edge_a\|} \quad (\text{mm/px})， \quad L_{base} = 40\ \text{mm（双码）或}\ 15\ \text{mm（单码降级）}$$

中心位移矢量 `Δp = (Δu, Δv) = (u − u₀, v − v₀)`（像素），则：

**（1）轴向滑移**（沿基线方向投影，直接以毫米计）：

$$a_x = \left( \Delta u \cos\theta_0 + \Delta v \sin\theta_0 \right) \cdot s$$

采用**当前帧**比例尺 $s$ 而非参考帧比例尺，是对轴向移动引起景深变化的一阶透视修正：像素位移与物距成反比，而比例尺与物距成正比，二者相乘即恢复物理位移的一阶量。

**（2）周向位移与滚转角 φ**（垂直基线方向投影后，经有效半径反解角度）：

$$p_{\perp} = \left( -\Delta u \sin\theta_0 + \Delta v \cos\theta_0 \right) \cdot s, \qquad
\varphi = \arcsin\!\left( \mathrm{clip}\!\left( \frac{p_{\perp}}{R_{TAG}}, -1, 1 \right) \right)$$

其中 $R_{TAG}$ 为**标志平面到管道轴线的垂直距离**（`R_TAG_MM`，当前标定值 395 mm）。其几何含义：子机绕管道轴线滚转 φ 时，码中心在以 $R_{TAG}$ 为半径的圆上运动，从轴线附近俯视，其在图像面内的横向位移分量为 $R_{TAG}\sin\varphi$，故反解得 φ。比值钳位到 [−1, 1] 防止大偏差下 `arcsin` 定义域越界。

**（3）航向角 ψ**（面内角差，含 −180°~180° 归一化）：

$$\psi = \mathrm{wrap}_{\pm 180}\!\left( \theta - \theta_0 \right)$$

**（4）透视收缩交叉校验角**（无符号）：

$$\varphi_{shape} = \arccos\!\left( \mathrm{clip}\!\left( \frac{edge_p}{edge_a}, -1, 1 \right) \right)$$

当码面相对光轴发生离面倾斜时，两组对边长度出现差异，可独立反解倾斜角。需要说明：在双码融合模式下，融合观测的 `edge_a` 与 `edge_p` 均取基线长度（代码 219–221 行），故 $\varphi_{shape}$ 退化为 0——该字段当前仅作为协议兼容保留，其交叉验证功能在单码模式（旧方案）中有效。这是本设计用双码基线方案替换单码方案后的已知冗余，不影响主判据。

**（5）周向纠偏弧长**（供运动规划换算）：

$$l_{arc} = R_{pipe} \cdot \varphi_{rad}, \qquad R_{pipe} = 250\ \text{mm（`PIPE_RADIUS_MM`）}$$

注意 $R_{TAG}$（角度反解有效半径）与 $R_{pipe}$（轮子行走弧长半径）物理含义不同、数值不同，前者影响测量标定，后者影响运动规划，二者不可混用。

**（6）对准判据**（代码 169–172 行）：

$$aligned = \left( |\varphi| \le 0.5° \right) \land \left( |\psi| \le 0.5° \right) \land \left( |a_x| \le 2\ \text{mm} \right)$$

容差值与子机执行端死区（`ADJ_TOL_PHI/PSI/AX = 0.5/0.5/2.0`）一致，保证"视觉判定对准"与"执行端不再响应"的边界重合，避免闭环在死区边缘振荡。

### 3.4.3 几何常数表与标定要求

| 常数 | 当前值 | 物理意义 | 标定方式 |
|---|---|---|---|
| `DUAL_TAG_SEP_MM` | 40.0 mm | 双码中心间距，比例尺基准 | 打印/粘贴后卡尺实测 |
| `TAG_REAL_MM` | 15.0 mm | 单码黑框边长，单码降级时比例尺基准 | 同上 |
| `R_TAG_MM` | 395.0 mm | 标志平面到管道轴线的垂直距离，φ 反解有效半径 | **贴装后必须实测**（继承自视觉固件 `tag_utils` 注释） |
| `PIPE_RADIUS_MM` | 250.0 mm | 管道半径，φ→弧长换算 | 结构设计值 |
| `TAG_ID_A/B` | 0 / 1 | 双码身份，基线方向约定（小→大） | 粘贴方向约定 |

**跨端一致性约束**：`PIPE_RADIUS_MM` 同时出现在 K230（代码 34 行）、子机 `main.c`（`ADJ_PIPE_R_MM`）与 App `align.js` 三处，任何一处修改必须同步，否则周向迭代扣减将出错（见 `ALIGN_CODE_MAP.md` §5）。

### 3.4.4 模型假设与适用范围

1. **小角度正交近似**：φ 反解采用单圆正弦模型，假设相机光轴近似通过管道轴线；φ 在闭环收敛域（±4° 内）非线性误差可忽略；
2. **刚体假设**：单码反推假定两码与车身无相对位移；
3. **平面标志假设**：忽略管壁曲率对码面成像的畸变影响（码面尺寸 15/40 mm 相对 500 mm 管径曲率影响为亚像素量级）；
4. **比例尺一致性**：假设同一帧内两码物距一致（码面共面）。

## 3.5 多帧共识滤波

单帧检测存在角点抖动与偶发误解码。为在不引入明显时延的前提下稳定输出，设计了**滑窗共识机制**（`push_consensus()`，代码 387 行）：

- 维护长度为 `ALIGN_FRAMES = 2` 的观测滑窗，仅输出有效观测入窗；
- 窗满后对 `(u, v, θ, edge_a)` 取**算术平均**，`hamming` 取窗口内**最大值**（保守置信度），`tags_used` 取窗口内**最小值**（一旦某帧降级为单码，整窗结果标记为低置信）；
- 标定用的 `tag_off` 按码 ID 分别平均；
- `sync_consensus()`（代码 1205 行）在 5 s 超时内循环取帧直至凑满共识窗，超时返回失败原因码。

共识帧数 N 是**时延—稳定性**的折中参数：N=2 时单次测量时延 ≈ 2×单帧检测耗时（实测 HTTP 全链路 412 ms，见 3.7.2），同时可将白噪声方差降低约一半；若现场抖动加剧，可增大 N（时延线性增加），该参数为单常量可调设计。

## 3.6 嵌入式软件设计与实现

### 3.6.1 软件架构

全部板端逻辑以单文件 MicroPython 实现（1833 行），采用**单线程事件循环**架构（CanMV 主循环不支持自由多线程），按职责分为四层：

| 层 | 关键函数（行号） | 职责 |
|---|---|---|
| 检测解算层 | `obs_from_apriltag`(231)、`fuse_dual_obs`(184)、`synthesize_dual_from_one`(286)、`detect_dual_from_tags`(331)、`delta_report`(137)、`push_consensus`(387) | 纯函数式观测/解算，无 I/O 副作用 |
| 会话状态层 | `set_ref_from_obs`(460)、`clear_ref`(482)、全局态 `g_ref/g_last_dev/g_last_json` | 参考位管理、最近测量缓存 |
| 采集层 | `camera_init/pause/resume/deinit`(829–917)、`vision_start/stop`(921/959)、`capture_preview`(1073)、`capture_detect_update`(1139)、`sync_consensus`(1205) | 传感器生命周期与帧调度 |
| 服务层 | `run_servers`(1655)、`handle_control_client`(1475)、MJPEG 推流(1617–1645)、UDP 发现(674–795)、内嵌控制页 `PAGE_HTML` | HTTP/MJPEG/UDP 服务与功耗策略 |

### 3.6.2 摄像头生命周期与功耗管理

K230 固件对 `Sensor`/`MediaManager` 的销毁重建较脆弱（二次 deinit/init 易失败），为此实现**软停—恢复**生命周期：

- `camera_init()`：首次创建 Sensor 并**仅一次** `MediaManager.init()`（`g_media_inited` 守卫）；
- `camera_pause()`（结束）：仅 `sensor.stop()` 停采，**不拆除** MediaManager，保留 Sensor 对象与参考位；
- `camera_resume()`（再开始）：`stop → reset → 重设分辨率/像素格式 → run` 官方时序；失败则 `force=True` 整体重建兜底；
- `camera_deinit()`：仅进程退出时完整拆除。

功耗策略：

- **上电默认休眠**：仅启动 WiFi 与控制服务，摄像头不工作，主循环以 80 ms 周期空转；
- **显式开关**：网页/App 经 `/align/start`、`/align/stop` 控制采集；
- **流自动唤醒**：App 拉取 `:81/stream` 时自动开采（免先调 start），但 `/align/stop` 后 8 s 内（`STREAM_DENY_AFTER_STOP_MS`）拒绝自动唤醒，防止 App 端自动重连立即把摄像头重新点亮——这是实测中发现的"关不掉"问题针对性设计。

### 3.6.3 分时复用与实时性保障

单线程架构下，检测（数十至数百毫秒）与推流（持续）竞争 CPU，若处理不当会造成浏览器画面长时间冻结或测量超时。采取三项措施：

1. **预览节流**：推流帧间隔 100 ms（`PREVIEW_INTERVAL_MS`，约 10 fps）；其中**仅在已记参考时**每 300 ms（`PREVIEW_DETECT_INTERVAL_MS`）执行一次完整检码并将结果写入 `g_last_dev/g_last_json`，供 App 以 300 ms 周期轮询 `/align/get` 获得近实时偏差；未检码帧只叠加参考位十字标记，避免把上一帧结果误刷为 `no_tag`；
2. **测量间隙泵流**：`/align/ref`、`/align/once` 的共识测量循环内，每检完一帧即调用 `pump_stream_frame()`（代码 1188 行）把当前 JPEG 推给浏览器，测量期间画面不冻结；
3. **推流独立监听**：控制口（:80）与流口（:81）双 `listen` socket，每轮循环优先处理控制请求，测量请求不会被推流阻塞；HTTP 响应体按 4096 B 分块发送，规避 RT-Smart 协议栈长包发送超时。

内存方面，每次检码后执行 `gc.collect()`，JPEG 编码使用 `memoryview` 分块发送，避免 MicroPython 堆碎片化导致的长期运行内存枯竭。

### 3.6.4 网络服务与接口设计

**HTTP API**（:80，全部响应带 `Access-Control-Allow-Origin: *` 与 `no-store`）：

| 路径 | 方法语义 | 返回 |
|---|---|---|
| `/`、`/index.html` | 内嵌控制页（开始/结束/测一次/记参考/清除） | HTML |
| `/status`、`/align/status` | 运行状态、参考位、最近偏差、几何配置 | 纯文本 |
| `/align/start` `/align/stop` | 开采 / 软停（含 8 s 流拒绝窗口） | JSON |
| `/align/ref` `?clear=1` | 记参考（强制双码共识）/ 清参考 | JSON（含参考位坐标） |
| `/align/once` | 触发一次共识测量（闭环每轮调用） | JSON 偏差 |
| `/align/get` | 读取最近测量缓存（监视轮询，不触发检码） | JSON |

**测量结果 JSON**（`align_json_ok()`，代码 357 行）关键字段：

```
ok, dt_ms, id, hamming, phi_deg, psi_deg, phi_shape_deg,

```

其中 `tags`（2=双码 / 1=单码反推）与 `hamming` 为置信度评估提供了显式依据。

**UDP 自动发现**（:48899，与母机/子机同协议）：应答 App 广播的 `WALLBOT_DISCOVER`（返回 `WALLBOT:camchild:<ip>`），并**每 2 s 主动广播**自身地址至全网广播与定向地址——因平板热点后台无法枚举接入设备，主动广播保证 App "常驻扫描必然收到"，解决了纯问答式发现因时序错配而失联的问题。

### 3.6.5 部署与可靠性设计

固件经 `flash_k230.py` 以串口 raw REPL + base64 分块方式写入板端 `/sdcard/main.py`，上电自启；通过 USB CDC 串口 VID/PID（`1209:ABD1`）与 `Kendryte/CanMV` 关键字自动识别端口，避免与母机（`/dev/ttyACM1`）误烧。WiFi 支持 STA（默认连平板热点 `robot`，25 s 超时明确提示）/ AP（`k230-align`，WPA2）双模，AP 配置对多版本固件的参数形态做多候选自适应尝试，解决冷启动 AP 起不来与开放热点不被支持的兼容性问题。主循环关键路径嵌入 `os.exitpoint()`，保证 IDE/串口可随时安全中断。

## 3.7 系统集成与实验验证

### 3.7.1 集成链路与闭环工作流

视觉纠偏闭环的完整时序（母机 `align_vision` 状态机驱动，50 ms 一拍）：

```
① 记参考：App →(0x26)→ 母机 →(GET /align/ref)→ K230 双码共识 → 存参考位
② App 发 0x22 启动闭环 → 母机 /align/start + TSTA → 子机就绪(TSTB)
③ 每轮循环：母机 GET /align/once（强制重新测量，不读缓存）
     ├─ aligned 连击 ≥ 2 → 判收敛，结束
     └─ 否则 增益/限幅/死区判定 → ADJ,φ,ψ,ax → NRF → 子机三段式执行 → DONE
④ 每轮母机将 0x88（状态/轮次/偏差）与 0x89（K230 原始 JSON）推给 App
```

**闭环期间必须停止 App 监视轮询**：K230 为单线程服务，监视轮询（/align/get）与闭环测量（/align/once）虽不直接冲突（前者读缓存），但推流检码与共识测量共享采集管线，App 侧在闭环启动时自动挂起监视，避免测量节拍被干扰。

### 3.7.2 实机闭环实验

2026-10-25 完成三端真实链路联调（`firmware/ALIGN_VISION_TEST.md` 记录）。一次典型成功闭环的关键数据：

| 单轮纠偏全程 | **6.2 s** | 子机三段式运动占主要耗时，视觉测量仅占约 7% |

**（2）收敛过程**（增益 30%）：

### 3.7.3 测量分辨率与误差传递分析

以参考位实测基线 96 px（40 mm）为基准，比例尺 $s ≈ 0.42$ mm/px（测试日志 `ref ... edge=96.0`）。设角点中心定位误差 σ_u ≈ 0.1–0.3 px（AprilTag 解码亚像素精度），各自由度的理论分辨率/噪声水平估算如下：

| 自由度 | 传递关系 | 单帧噪声水平 | 判据裕度 |
|---|---|---|---|
| φ | $\sigma_\varphi \approx s\,\sigma_u / R_{TAG}$（弧度） | ≈ 0.006°–0.018°（1 px 位移对应 0.061°） | 充裕（判据 0.5° ≈ 8 px 位移） |
| ax | $\sigma_{ax} \approx s\,\sigma_u$ | ≈ 0.04–0.13 mm | 充裕（判据 2 mm ≈ 5 px） |
| ψ | $\sigma_\psi \approx \sqrt{2}\,\sigma_u / dist_{px}$（弧度） | ≈ 0.09°–0.25° | **最紧张**（判据 0.5°） |

三点结论：

1. **φ 与 ax 为位置量测量**，条件数好，精度主要受 $R_{TAG}$ 标定误差的一阶缩放（$\mathrm{d}\varphi/\varphi = \mathrm{d}R_{TAG}/R_{TAG}$）；
2. **ψ 为短基线角度量测量**，是三自由度中误差传递最剧烈的一项（基线 96 px 上叠加两码中心噪声），实测收敛残差 ψ=0.20° 与该估算量级一致。若需进一步收紧 ψ 判据，优先手段是**加大双码间距**（40 mm → 60/80 mm，基线像素数线性增加）而非提高检测分辨率；
3. 共识滤波（N=2）使上述噪声方差近似减半，实测残差稳定在判据的 40%–80% 区间，闭环无振荡，与死区设置（0.5°/2 mm，执行端）配合形成稳定收敛域。

### 3.7.4 误差来源与改进方向

| 误差源 | 影响 | 现状/对策 |
|---|---|---|
| $R_{TAG}$ 标定误差 | φ 系统性比例偏差 | 已知必须实测项；改进：闭环中用已知位移反标定 |
| 双码粘贴方向与基线 ≠ 管道轴向 | ax 与周向分量投影串扰 | 粘贴工序保证；或标定期增加角补偿项 |
| 轴向大位移时的透视非线性 | ax 高阶误差 | 命令限幅 ±30 mm 内为一阶可忽略；可引入景深迭代修正 |
| 单码降级测量的比例尺切换（40→15 mm 基准） | 降级帧噪声增大 | `tags=1` 显式标注；可按码数加权共识 |
| 共识窗仅 2 帧 | 残余抖动 | 参数化可调；或引入中值滤波 |
| 光照不足 / 运动模糊 | `no_tag` 率上升 | 闭环重试机制（母机 `AV_HTTP_FAIL_MAX`、失败分类重试）已兜底 |

## 3.8 本章小结

本章完成了管道机器人视觉纠偏闭环中摄像头检测子系统的设计与实现：

1. **方案层**：论证并确定"双 AprilTag（tag36h11，ID0+1，40 mm 基线）+ 俯视单目"的基准方案，以 K230 CanMV 为检测平台，兼顾算力、生态、通信与功耗；
2. **算法层**：建立了从单码观测 → 双码刚体融合 → 参考位标定 → 三自由度偏差解算（φ=arcsin(p⊥/R_TAG)、ψ=Δθ、ax=轴向投影）的完整测量模型，比例尺由基线自标定、安装旋转由参考位吸收，并新增单码刚体反推实现遮挡降级测量；
3. **实现层**：在单线程 MicroPython 环境下以"软停—恢复"摄像头生命周期、预览/检码分时复用、测量间隙泵流等机制，同时保障了 10 fps 预览、412 ms 单次测量与功耗目标；以 HTTP/JSON/MJPEG/UDP 发现构成完整服务化接口；
4. **验证层**：实机三端闭环实验表明单次测量 412 ms、单轮纠偏 6.2 s、闭环单轮收敛，终态残差 φ=0.40°/ψ=0.20°/ax=1.2 mm，满足并优于当前收敛判据；误差传递分析指出 ψ 为精度瓶颈自由度，给出了加大基线的改进路径。
